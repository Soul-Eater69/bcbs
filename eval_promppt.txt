You are evaluating how much information from a stage is reflected in a human-written epic.

Your task is limited to identifying stage-information coverage.

Do not evaluate the quality of the epic.
Do not rewrite or improve any text.
Do not claim that the stage caused the epic content.
Do not add information that is not present in the input.
Do not calculate or return coverage percentages.

## Stage fields

The stage contains:

* Stage name
* Stage description
* Entrance criteria
* Exit criteria

## Epic fields

The epic contains three string fields:

* Title
* Description
* Success criteria

## Evaluation instructions

1. Internally identify the distinct meaningful pieces of information contained in each stage field.

Do not return these internal pieces individually.

Use these rules consistently:

* A non-empty stage name normally contains one meaningful item.
* Each independent entrance criterion normally counts as one meaningful item.
* Each independent exit criterion normally counts as one meaningful item.
* Split a stage description only when it clearly contains multiple independent meanings.
* Do not split one meaning merely because it contains multiple words or phrases.
* Do not count duplicate or repeated wording within the same stage field as additional information.

2. For every stage field, determine:

* `total_items`: Number of meaningful information items available in that field.
* `covered_items`: Number of those items clearly reflected somewhere in the epic.

3. Compare every stage field against all three epic fields:

* Title
* Description
* Success criteria

4. Count a stage-information item as covered only when the epic contains:

* The same meaning directly, or
* A clear semantic paraphrase

5. Do not count:

* A shared word with a different meaning
* Weak or indirect associations
* General topic similarity
* Generic business terminology
* Information requiring substantial inference

6. Count each meaningful stage item only once within its source stage field, even when it appears in multiple epic fields.

For example, when one exit-criteria item appears in both the epic description and success criteria:

* Count it as one covered exit-criteria item
* Include both exact quotations in the evidence when useful

7. For every stage field with at least one covered item, provide exact supporting evidence copied from the epic.

Each evidence item must contain:

* The epic field where the evidence appears
* The exact matching text copied from that epic field

8. Evidence may be an exact substring or the complete epic field.

Do not rewrite, shorten, summarize, correct, or paraphrase the evidence.

9. The same epic quotation may support multiple stage fields only when it genuinely reflects information from each field.

10. For `stage_usage_locations`, return `true` when at least one reliable piece of stage information is reflected in that epic field.

11. When a stage field is non-empty but none of its information is reflected:

* Return its correct `total_items`
* Set `covered_items` to `0`
* Return an empty evidence array

12. When a stage field is empty or unavailable:

* Set `total_items` to `0`
* Set `covered_items` to `0`
* Return an empty evidence array

13. `covered_items` must never be greater than `total_items`.
